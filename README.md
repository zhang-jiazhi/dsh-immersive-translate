# dsh-immersive-translate

把「沉浸式翻译」移植成 DSH 桌面版插件：**在 DSH 窗口里就地翻译**——直接替换页面上的文字（含对话与思维链），鼠标悬停看原文。

翻译默认走**沉浸式翻译自带的免费服务**，不消耗你在 DSH 里配置的模型额度；同时移植了**沉浸式翻译账号**体系（登录后可用 Pro 引擎）。

---

## 完成标准与验证结果

**完成标准**：翻译链路走插件自带的免费模型而不是你的模型；登录账号功能可用；除桌面版跑不通的部分外，原插件能力都已在插件里生效。

| 项 | 证据 |
|---|---|
| **自带免费服务** | 腾讯交互翻译（`transmart.qq.com/api/imt`，扩展 `group:"free"`）实测 **330ms** 返回真实译文；`Hello world → 您好，世界`、`Practice makes perfect. → 熟能生巧。` |
| **不占你的模型** | `normalizeConfig` 默认 `engine:'auto'` / `useDshModel:false` / `allowModelFallback:false`；免费服务失败默认**不回退**到你的模型 |
| **登录账号** | `verifyAccountToken` 对接真实接口 `api2.immersivetranslate.cn/v1/user`：空令牌→「令牌为空」，假令牌→「令牌无效或已过期」（真实 401） |
| **账号令牌持久化** | 保存设置**不会清掉**已登录令牌（有回归测试守着） |
| **就地翻译** | 真实 DSH 页面上点悬浮球 → 文字就地变译文；`[data-imt-done]` 命中；悬停浮出原文；还原一字不差 |
| **长会话/思维链** | 600 块长页全部翻完（含最后一块）；真实会话里思维链 85/85 |
| **多引擎可选** | `auto` / `transmart` / `zhipu-free` / `google` / `account`（Pro）/ `dsh-model` |
| **服务自检** | `GET /api/dsh-immersive-translate/services` 逐个探测并回报"哪个慢/哪个不通" |
| **旧宿主守卫** | 宿主未上报协议版本时**拒绝翻译**并提示重启（否则会偷偷走你的模型）——有回归测试守着 |
| **内联元素不丢** | 占位符改用 `[[§n]]`（旧 `⟦n⟧` 会被腾讯改写：`GitHub⟦0⟧` → `GitHub下载`，甚至吞掉占位符导致 `<a>` 丢失）——真实 DSH 页面上验证 `GitHub` 不再变成日期 |
| **悬浮球不被样式回收带走** | 关键定位内联写死：样式表被误删后球仍 `fixed`、仍在视口内（实测此前 `top 380 → 800` 跑出视口 = "开关不见了"）；位置越界自动夹回 |

| **设置页两个开关** | 「打开页面自动翻译」「显示悬浮球」都是 `role=switch` 拨杆，保存后**当场生效**（不必刷新页面） |
| **只跳过纯中文** | 夹了中文的英文句照常翻译（`Click the 设置 button…` → `单击设置按钮打开存储库`）；仅纯中文/数字/符号块跳过 |
| **批失败自动重试** | 3 次指数退避。实测前两批故意 500 → 30/30 块仍全部译出，0 遗漏 |
| **漏译不再被"锁死"** | 宿主不再用原文冒充译文：漏译条目走 `missing` 上报，客户端保持原文、**不打 `data-imt-done`**，并主动重排重试（不依赖页面变化） |

| 测试 | **97 项全过**（抽取器 19 + 宿主 45 + 真实浏览器 33），`npm test` |

## 安装

插件目录：`~/.dsh/local-plugins/dsh-immersive-translate`（本机已就位）

### 正式装配（本机已配好）

`~/.dsh/profiles/desktop/package.json` 两处都要有：

```jsonc
{
  "dependencies": {
    "@dsh-external/dsh-immersive-translate": "link:/Users/<你>/.dsh/local-plugins/dsh-immersive-translate"
  },
  "dsh": { "profile": { "bundles": ["@dsh-external/dsh-immersive-translate"] } }
}
```

- `dependencies` 提供模块解析，`bundles` 才让它进入装配树
- 改完 `npm install` 后**重启 DSH**

> ⚠️ **宿主代码改动必须重启 DSH 才生效**。改 `lib/index.js`（新增路由/引擎）后不重启，新路由不会注册——表现为访问新接口返回 `401 unauthorized`。

### 前置条件

- DSH ≥ 0.1.7（用到 `ctx.webServer`、`ctx.tools`）
- **不需要**配置模型：默认走自带免费服务

## 使用

1. 点右下角**圆形悬浮球**（可拖动、位置记忆）
2. 点「翻译此页」→ 页面文字就地变译文（默认仅译文，悬停看原文）；按钮角标显示已译块数
3. 有英文内容时才有得翻：DSH 界面本身是中文，会被语言判断正确跳过
4. 选中文字 → 浮出「译」→ 划词翻译

### 设置 → 沉浸式翻译

| 项 | 说明 |
|---|---|
| **翻译引擎** | 默认「自带免费服务」；可选 transmart / GLM 免费网关 / Google / 账号 Pro / 借用 DSH 模型 |
| **账号** | 粘贴沉浸式翻译令牌 → 登录；显示已登录用户；可退出 |
| 免费服务自检 | 点一下逐个探测服务可用性 |
| 目标语言 | 9 种；已是目标语言的内容自动跳过 |
| 显示模式 | 仅译文（默认）/ 双语对照 |
| 用户规则 JSON | 同扩展写法，`excludeSelectors` 命中区域不翻 |

### 账号登录怎么拿令牌

原扩展通过浏览器扩展权限自动截获登录页回传的令牌（存在 `chrome.storage.local` 的 `user_token`）。桌面插件没有这个权限，所以改为**粘贴令牌**：

1. 登录 `https://immersivetranslate.com/accounts/login`
2. 从账号后台/会话中取出令牌
3. 粘贴到「设置 → 沉浸式翻译 → 账号」，点「登录」（会先校验再落盘）

## 排查

| 症状 | 处理 |
|---|---|
| 点翻译弹「宿主代码未重载：请重启 DSH」 | **属预期保护**：宿主进程仍是旧代码，翻译会走你自己的模型，所以被拦下了。重启 DSH 即可 |
| 访问新接口返回 `401 unauthorized` | 宿主代码未重载：**重启 DSH** |
| 点翻译没反应 | 页面已是目标语言（中文界面+目标中文会被正确跳过）；看提示条或点「免费服务自检」 |
| 找不到悬浮球/开关 | 球已被夹回视口；若仍不见，看窗口是否被拖到极小、或被设置页「悬浮球」开关关掉了 |
| 有些句子没翻译 | 本该整句跳过的是**纯中文**；夹了中文的英文句应当翻译。若确有一整块没动，看提示条的「失败」计数（瞬时故障已自动重试 3 次） |
| 自动翻译开了没反应 | 宿主需重启后才认得这个键（客户端已用本地镜像兜底，应当当场生效） |
| 只有部分块翻译 | 用「用户规则」调 `excludeSelectors`；确认目标语言设置 |
| 提示条说"没有需要翻译的内容" | 属预期：界面本身已是目标语言 |
| 想翻右侧栏网页 / PDF / 视频字幕 | **做不到**，见下 |

## 设计

**为什么默认不用 DSH 模型**：你要的是"原插件自带的免费翻译"。所以默认引擎是扩展自己声明为免费的服务，且**免费服务失败默认不回退**到你的模型（要回退得显式开 `allowModelFallback`），避免悄悄花掉额度。

**免费服务的来源**：端点与语言码全部提取自扩展的 `default_config.json`（`translationServices`）与 `background.js`，写进 `FREE_SERVICES` 并有测试断言，上游改动时测试会失败而不是静默出错。

**占位符为什么要用 `[[§n]]`**：内联元素（`<a>`/`<strong>`）在送翻译时用占位符占位，译文回来后按占位符把元素搬回去。占位符必须是机器翻译**原样保留**的形态——实测腾讯交互翻译会改写旧标记 `⟦n⟧`（`GitHub⟦0⟧` → `GitHub下载`；`Click here⟦0⟧now please` → `请点击这里`，占位符整段消失，`<a>` 就丢了）。候选标记经 10 类位置压力测试后选定 `[[§n]]`（10/10 保留）。这个坑原先漏检，是因为测试用的假宿主只做字符串拼接、永远保留占位符；现已补上一条**对真实服务**验标记形态的用例。

**为什么"自动翻译"原先不生效**：宿主落盘走 `writeSettingsPatch`，它按 `key in DEFAULTS` 做白名单过滤。`autoTranslate` 当初没登记进 `DEFAULTS`，于是**保存时被静默丢弃**，刷新即丢失——看起来就是"这个功能没用"。现已登记 `autoTranslate`/`showBall`/`freeConcurrency` 三个键，并有测试钉住。

**为什么需要"本地镜像"**：宿主是 ESM 模块，改宿主代码必须重启 DSH 才生效；而客户端 bundle 是热更新的。于是会出现"新界面 + 旧宿主"，新开关保存后被旧宿主的白名单丢掉。为此客户端把三个界面偏好额外镜像在 `localStorage`（`dsh-immersive-translate:prefs:v1`），宿主没上报该键时用它兜底、**当场生效**；宿主一旦上报就以后者为准，不形成第二个事实源。

**为什么本地镜像的写入顺序很关键**：保存流程是"写镜像 → `load()` 回填表单"。曾把镜像写在 `load()` 之后，于是首次保存时 `load()` 读到的是**还没更新**的镜像，开关在视觉上"弹回原位"——用户会以为"开关点了没用"。现已颠倒顺序，并有专门的回归用例（用一个不认新键的旧宿主复现）。

**为什么"夹中文的英文句"曾被漏翻**：旧语言判定先执行 `replace(/[A-Za-z][A-Za-z0-9_.-]*/g, ' ')` 再统计"拉丁词"，而那个正则匹配的其实是**普通英文单词**（不只标识符），于是英文词全被删光、`latinWords` 恒为 0，任何含汉字的句子都算成 100% 中文而被整句跳过。现改为直接比"汉字数 vs 拉丁字母数"，并取高阈值 0.8：只有汉字压倒性多数（拉丁字母仅零星单位/编号）才跳过。注意占比阈值无法区分 `Hello 世界`（该翻，0.286）与 `Token 统计`（可跳过，0.286）——两者占比完全相同，因此按用户明确要求"只跳过纯中文"，优先保证不漏内容。

**为什么"漏翻"曾经修不掉**：宿主拿不到译文时会**用原文回填** `translations`。原文与真译文在返回值里长得一样，客户端于是把它当译文写进页面、还打上 `data-imt-done` —— 这块内容此后被 `collect` 当成"已翻"永久跳过，**再也不会重试**。实测证据：本会话末段 `No argv info there. I have enough. …` 整句仍是英文，却带着 `done` 标记；`__imtRecord` 显示 `srcText === dstText`。修法是让漏译可被区分：宿主改报 `missing: [id…]`，客户端对这些条目一个字都不改、不打标记，并在本轮结束后主动再排一轮（最多 3 轮退避重试）。对**尚未重启**的旧宿主，客户端另有一层兼容：旧宿主漏译时会原样回显我们发去的文本，若该文本"含空白、有 ≥2 个英文词、且看起来仍不像目标语言"，就判定为漏译同样跳过 —— 这一层必须保守，否则会把 `tokenrhythm/deepseek-flashMax`、`/Users/…` 这类**本该原样保留**的内容误判成失败，导致无限重试、球一直变红（实测踩过：104 块已翻对却报"2 块失败"）。

**为什么 `failed` 要每轮重置**：它的语义是"这一轮有多少条没落上"，不是"从开翻译至今累计失败过多少次"。原先累加，导致**最终全部成功之后球依然是红色**、提示条一直挂着"请重启 DSH"（实测：106 块全译对，球仍显示 error）。现在每轮清零，重试用尽后才把 `unresolved.size` 定为终值。

**为什么语言判据不看"比例阈值"**：曾用 `汉字占比 >= 0.8` 判断"已是中文"。实测它会在"中文夹标识符"上翻车：`比较备份和Web配置文件清单`（11 汉字 / 3 拉丁 = 0.786）刚好卡在阈值下方 → 被送去翻译；旧宿主对中文原样回显 → 又被"回显兜底"判成漏译 → 无限重试、球变红。比例阈值天生拧巴，同一比例会对应相反期望（`Hello 世界` 0.29 要翻，`Token 统计` 0.29 可跳）。现改为按**拉丁词个数**判主体：成句英文会攒出 ≥4 个英文词（该翻），中文标签只夹 1~2 个标识符（该跳）；另外汉字 ≤2 且有英文词时也算夹心句要翻。

**为什么浮层定位要内联写死**：DSH 模块系统物化插件时会把**所有没有 `data-plugin` 的 `<style>`** 划归当次物化的插件，该插件重载时再一并删除（`dsh-client-modules` 的 `claimStyles`/`removeOwnedStyles`）。2026-09-25 桌面端"主界面能被滚走"的事故就是这么来的（drop-path 的样式被连坐删除）。本插件同样可能落在被删窗口里——实测 `.imt-ball-wrap` 会从 `fixed` 退化成 `static`，球被挤到文档末尾（`top 380 → 800`，正好在视口外），表现就是**"悬浮球/开关不见了"**。因此悬浮球、菜单、提示条、悬停浮层、划词浮层的**定位与显隐都内联写死**，任何样式表丢失都不影响可见、可点、可用。

**为什么加显式开关**：原版悬浮球里是一个真正的拨杆开关（`aria-pressed` + `switch-thumb`）。本插件原先只在菜单项文案上隐式表达状态（「翻译此页」⇄「还原原文」），用户反馈"开关不见了"——现在菜单顶部是一个一眼可辨、读屏可读（`role=switch` + `aria-checked`）的拨杆行。

**为什么要有"旧宿主守卫"**：DSH 宿主代码改动**必须重启进程**才生效（ESM 已缓存），而客户端 bundle 会随文件改动重建。于是可能出现"界面是新版、翻译却仍走旧链路"的错配——后果是**悄悄花掉你自己的模型额度**，正是本轮明确要避免的。宿主的 settings 响应里带 `hostProtocol`，客户端比对不上就拒绝翻译并提示重启；宁可不翻，也不偷偷扣额度。

**注入引擎要点**：只翻叶子块；穿透 `display:contents`（DSH 界面大量使用）；超长叶子块继续下钻；内联元素用占位符 `[[§n]]` 精确重建（链接/结构不丢）；`code`/`pre` 保留且内部不翻；单轮 240 块上限会**继续多轮**直到消化完（长会话/思维链能翻全的关键）；语言判断按"剔除标识符后的汉字占比"，避免把中文+英文标识符整屏送去翻译。

**三道硬约束**（都踩过，都有回归测试）：

1. `inject` 必须列全用到的服务，否则整块回滚（路由与工具全挂不上）
2. 每个 `register` 必须包在 `ctx.effect(...)`，否则热重载残留孤儿路由
3. `lib/client.js` 里 `__ModuleLoader__.load({ id })` 的 id 必须等于 `package.json` 的 `name`
